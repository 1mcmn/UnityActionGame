## 一、核心设计（先定大方向，再写代码）

### 1.1 数据流

```
技能编辑器窗口(Editor) ──编辑──→ SkillLibrary(资产：技能ID索引表)
                                     │ 每个技能 SkillConfig
                                     │    ├─ skillId / skillName
                                     │    └─ 组件列表 List<SkillComponent>（每个组件本身是资产，可被多个技能共享）
                                     ↓ 运行时按 ID 查找
                              SkillManager.PlaySkill(id, caster, target)
                                     ↓
                     SkillInstance（释放 → 运行 → 打断/结束，全程清理）
                                     ↓
              组件各自干活：播动画 / 帧音效 / 判定窗口 / 伤害 / 击打反馈 / 无敌帧
```

### 1.2 三个"先拍板"的关键决策（阶段 1 动笔前必须选，推荐项已标 ✅）

| 决策点 | ✅ 推荐 | 备选 | 理由 |
|---|---|---|---|
| 组件怎么存 | ✅ **组件内嵌技能资产（[SerializeReference]）**（v3 决策反转，用户实测后拍板） | 独立 ScriptableObject 资产引用 | 界面内直接添加/命名/调参，零资产文件（策划友好，参考视频同款）；"全局组件库/模板"降级论文展望 |
| 组件父子层级 | **v1 扁平列表**，判定组件里"引用"伤害/反馈组件（组合关系） | 真正树形父子结构 | 树形结构编辑器复杂度翻倍；引用关系已能实现"判定组件挂伤害+反馈"的效果，树形放论文展望 |
| 技能播动画的方式 | **播放动画机已有状态名**（stateName），如 "Attack" | AnimatorOverrideController 动态换 clip | 你的动画机状态已存在；override 是进阶功能放展望。帧号从该状态的 clip 读（GetCurrentAnimatorClipInfo） |
| 与现有战斗的关系 | **共存迁移**：新技能系统独立运行，先做"上捞斩 demo"（新按键），老连击代码不动 | 重写 PlayerCombat 全部迁移 | 重写 = 弄崩现有可玩闭环的高风险操作，答辩前赌不起 |

### 1.3 组件基类与生命周期（系统的宪法，先背下来）

```csharp
// 组件 = 资产（ScriptableObject），生命周期四态：
// OnStart(释放) → OnTick(每帧运行) → OnEnd(正常结束) / OnInterrupt(被打断)
public abstract class SkillComponent : ScriptableObject
{
    public abstract void OnStart(SkillContext ctx);    // 释放瞬间，只调一次
    public abstract void OnTick(SkillContext ctx);     // 运行期每帧
    public abstract void OnEnd(SkillContext ctx);      // 播完正常收尾
    public abstract void OnInterrupt(SkillContext ctx);// 被打断，必须清理干净（关判定区/无敌帧/音效）
}
```

## 三、各阶段详细

### 阶段 1：数据层（2-3 天）

**功能**
1. `Assets/Scripts/SkillSystem/SkillComponent.cs`：抽象基类（见 1.3）
2. `SkillContext.cs`：技能上下文——`Transform caster`、`Vector3 targetPos`、`Transform target`（携带释放者信息）
3. `SkillConfig.cs`：`skillId`（唯一字符串）、`skillName`、`List<SkillComponent> components`
4. `SkillLibrary.cs`：`List<SkillConfig> skills` + `Get(string id)` 按 ID 查技能
5. 三个 `[CreateAssetMenu]`：技能、库、组件（组件菜单下一阶段随组件类型加）

**目标**：能在 Project 里右键创建库资产和技能资产，Inspector 填 ID、挂组件引用。

**验收**：编译过；创建一个 `SkillLibrary` 资产和一个 `SkillConfig` 资产（ID 先手填 `player_uppercut`），Inspector 显示正常。

**学习点**：`ScriptableObject` 资产、`[CreateAssetMenu]`、抽象类
**坑提醒**：新文件记得等 Unity 刷 csproj（或手动加 `<Compile Include>`），否则 CS0246；不写 `.meta`。

### 阶段 2：运行时框架（3-4 天，核心）

**功能**
1. `SkillManager.cs`（MonoBehaviour，挂玩家）：
   - `PlaySkill(string id, Transform caster, Vector3 targetPos)`：库查 ID → 创建 SkillInstance → 依次调组件 `OnStart`
   - `Update()` 里对运行中的技能逐帧调 `OnTick`；组件报告"播完"则转 `OnEnd` 并回收
   - `InterruptSkill(string id)`（或全部）：调所有组件 `OnInterrupt` → 回收
2. `SkillInstance.cs`：记录 `SkillLifecycleState { None, Released, Running, Ended, Interrupted }`、所属技能、开始时间；提供 `Finish()` / `RequestInterrupt()`
3. 生命周期日志：每次状态流转打 `Debug.Log("[Skill] xxx: Released→Running→Ended")`（论文"生命周期闭环"的证据）

**目标**：空技能（无组件）也能走完"释放→运行→结束/打断"，日志完整、无残留实例。

**验收**：代码里写死 `PlaySkill("test_empty", ...)` 调一次 → 日志按序打印；中途 `InterruptSkill` → 打印 Interrupted；技能结束后列表中无残留。

**学习点**：运行时实例管理、`Update` 驱动、生命周期模式
**坑提醒**：`OnStart/OnEnd` 各只调一次，`OnTick` 别在 `OnEnd` 后还跑（状态门控）；角色死亡时记得打断所有技能（否则判定区残留）。

### 阶段 3：内置组件（2-3 天，系统的"肉"）

**功能**（每个组件一个 `[CreateAssetMenu]`，放在 `Assets/Scripts/SkillSystem/Components/`）
1. `PlayAnimationComponent`：`stateName`（动画机状态名）、`crossFade`、`duration`（技能时长）；`OnStart` 播动画，`OnTick` 读当前 clip 进度，到 1 报结束；**内含帧事件列表 `List<SoundFrameEvent>`**
2. `SoundFrameEvent`（[Serializable]）：`frame`（整数帧）、`soundId`、`volume`、`loop`；`OnTick` 用"帧跨越检测"触发 `SoundManager.Play`（上版本计划书阶段 2 的原理：`当前帧 = normalizedTime × clip.length × frameRate(30)`）
3. `HitWindowComponent`：`hitWindowStartFrame/EndFrame`、`radius`（先圆形，论文写"形状可扩展"）、**引用** `DamageComponent` + `HitFeedbackComponent`；窗口内每帧 `OverlapSphere` 检测敌人，去重（一次挥击每敌一次）
4. `DamageComponent`：`damage` 数值
5. `HitFeedbackComponent`：命中音效前缀、顿帧时长/缩放、击退距离（命中时执行）
6. `InvincibleWindowComponent`：`startFrame/EndFrame` 无敌窗口（调 `PlayerCombat.SetInvulnerable`）

**目标**：数据侧完全具备"上捞斩 = 动画 + 判定窗 + 伤害 + 反馈 + 无敌帧"的组装能力。

**验收**：创建组件资产若干；纯代码 `PlaySkill("player_uppercut")`（组件用资产填好）→ 播放动画、到帧响音效、窗口内打中敌人扣血、窗口外打不中、结束/打断后判定区与无敌帧清零。

**学习点**：组合优于继承（判定组件引用伤害/反馈组件，就是"组件模式"的实战）、Animator 进度读取、OverlapSphere 时机控制
**坑提醒**：帧跨越检测要防"重复触发"和"跳帧漏触发"（用上一帧序号比较）；打断时无敌帧必须复位（否则角色永久无敌——这是论文"清理逻辑"的最好案例）。

### 阶段 4：编辑器窗口 v1（3-4 天，EditorWindow 入门）

**功能**
1. `Assets/Editor/SkillEditorWindow.cs`：菜单 `Tools/技能编辑器`
   - 顶部选 `SkillLibrary` 资产
   - 左：技能列表（ReorderableList：增删、选中）
   - 右：选中技能的 `skillId / skillName` + **组件列表**（ReorderableList：增删、上下移、展开组件资产 Inspector 风格字段）
   - "添加组件"按钮 → 弹出**同类组件资产列表**（用 `AssetDatabase.FindAssets("t:PlayAnimationComponent")` 等收集，列表里可选已有组件或"新建组件资产"）——这就是你"全局组件库"的第一形态：**库里已有同类组件直接引用**
2. 保存：`SerializedObject.ApplyModifiedProperties()` + `EditorUtility.SetDirty()`

**目标**：不动代码就能组装出一个技能（ID + 组件列表），保存即生效。

**验收**：编辑器里从零组装 `player_uppercut`（新建 5 个组件资产、填参数）→ 进游戏 `PlaySkill("player_uppercut")` 完整生效；不写一行新代码。

**学习点**：`EditorWindow`、`SerializedObject/SerializedProperty`、`ReorderableList`、`AssetDatabase.FindAssets`（编辑器专属 API）
**坑提醒**：Editor 代码必须放 `Assets/Editor/`；资产搜索要用 `t:类型名` 过滤；改完必须 SetDirty，否则不落盘。

### 阶段 5：编辑器进阶（2-3 天，论文亮点）

**功能**
1. 帧事件表格：选中 `PlayAnimationComponent` 时，下方显示帧事件 ReorderableList（帧号 / soundId 下拉 / 音量 / ▶ 试听）
2. 编辑器内试听：点 ▶ 直接播 soundId 对应的 clip（**参考你自己写的 `AudioBrowser.cs` 的编辑器试听代码**，换个数据源）
3. （可选加分）动画预览加事件：小面板用 `AnimationMode.SampleAnimationClip` 拖动时间轴，实时显示当前帧号，点"在此帧添加事件"自动填帧号——即你设想的"播放动画、看着帧加事件"
4. soundId 下拉数据源：从 `SoundLibrary` 资产收集 ID；拿不到则退化为手输字符串

**目标**：策划视角的"配音效"流程完整：选 clip → 拖时间轴 → 指定帧 → 选音效 → 试听。

**验收**：编辑器给上捞斩加"第 10 帧挥砍音效、第 14 帧命中音效"→ 进游戏两个音效都在正确帧响。

**学习点**：EditorGUI 控件族、编辑器内音频播放、`AnimationMode`（可选）

### 阶段 6：整合 demo（2-3 天，答辩演示核心）

**功能**
1. **玩家**：新按键（如 `J`）触发 `SkillManager.PlaySkill("player_uppercut", ...)`；老连击（左键）完全不动（共存迁移）
2. **Boss/怪物**：在 `EnemyAI` 死亡处把"播死亡动画"替换成 `PlaySkill("boss_down", ...)`——展示"特殊行为=调用技能 ID，无需新逻辑"；再给 `boss_down` 加判定+伤害组件演示"倒地震波"
3. **打断验证**：技能播放中被敌人击中 → 调 `InterruptSkill` → 判定区关闭、无敌帧复位、日志显示 Interrupted（论文"不残留污染"的证据）

**目标**：玩家和怪物两侧都用"ID 调用"释放技能；打断清理肉眼可验证。

**验收**：录屏能拍出三段：① 编辑器配出上捞斩 → 游戏里按 J 释放；② Boss 倒地调用技能 ID（含震波伤害）；③ 技能中途被打断，判定区立刻消失。

**学习点**：把"配置资产"和"运行时代码"接起来的最后一公里（序列化字段引用、查找、调用）

### 阶段 7：（时间允许）全局组件库窗口 + 简单连携状态机（3-4 天）

**功能**
1. `ComponentLibraryWindow.cs`：按类型分组列出所有组件资产 + 每个组件显示"被哪些技能引用"（`AssetDatabase.FindAssets("t:SkillConfig")` 遍历）；双击跳转。→ 完整实现"一处修改全局生效"的管理入口
2. 连携状态机（Inspector 列表式，不做图）：
   - `SkillConfig` 加 `List<SkillTransition> transitions`：`{ string conditionTrigger; string nextSkillId; }`
   - 技能层参数：`SetTrigger(string)` 存到一个技能级参数容器；技能结束时检查过渡条件 → 命中则自动 `PlaySkill(nextSkillId)`
   - Demo：上捞斩 → 回旋斩（攻击窗口内按 J 连携）
   - 图编辑器/虚拟节点/整理端点 → 论文设计版

**目标**：连招能在技能层配置出来，不需要碰 Animator。

**验收**：编辑器里配上捞斩→回旋斩过渡 → 游戏里按 J 两次自动连携。

**学习点**：跨资产引用查找、状态机的最小实现（条件表 + 运行时求值）

### 阶段 8：收尾（2-3 天）

**功能**
1. EditMode 测试：`SkillLibrary.Get(id)` 查无 ID 处理；生命周期调用顺序（OnStart→OnTick…→OnEnd/OnInterrupt 各一次）；帧跨越边界（事件帧=当前帧、帧乱序）
2. 5 分钟演示视频脚本：重点"编辑器改 → 游戏变"对比镜头（你设想的剪辑要点：配技能、改伤害、加音效事件、Boss 倒地）
3. 论文素材归档：每阶段的设计决策、踩坑（帧重复触发、无敌帧残留等）都是论文"实现与测试"章节的现成素材
