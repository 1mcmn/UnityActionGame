一、课题背景与意义
 
动作游戏是游戏市场中最具代表性的品类之一，其核心玩法围绕实时战斗、角色操控与敌人 AI 展开。一款动作游戏的战斗体验高度依赖精细的参数调校（连击窗口、伤害、判定时机、音效同步等）与高效的开发工具支撑。然而在实际开发中，这些战斗参数通常硬编码在脚本中或分散于多个 Inspector 面板，修改效率低、出错率高，且美术/策划人员难以直接参与调优。
 
本课题设计并实现一款第三人称动作游戏原型，同时开发配套的编辑器工具链，将战斗数据、怪物配置、音效资产管理等高频操作封装为可视化编辑窗口，降低非程序人员的协作门槛。课题融合游戏玩法开发与 Unity 编辑器扩展两大技术方向，具有工程实践价值。

3. 编辑器工具与游戏运行时通过 ScriptableObject 资产解耦，实现"编辑器修改，游戏即时生效"。

4.3 技能系统架构（数据驱动，本课题核心）
 
             SkillLibrary（技能 ID 索引表）           └─ SkillConfig（技能资产：skillId + 组件列表）                └─ List<SkillComponent>（[SerializeReference] 多态内嵌）                     ├─ PlayAnimationComponent（播动画 + 帧事件派发）                     ├─ HitWindowComponent（判定窗口：球/胶囊/盒三形状）                     │     ├─ 引用 DamageComponent（伤害数值）                     │     └─ 引用 HitFeedbackComponent（音效+顿帧）                     └─ InvincibleWindowComponent（无敌帧窗口）                 运行时：SkillManager（单例）.PlaySkill(id, caster, target)           → SkillInstance（生命周期：None→Released→Running→Ended/Interrupted）           → 组件四态：OnStart / OnTick / OnEnd / OnInterrupt（打断必清理：判定区、无敌帧零残留）             
 
设计要点：
组件模式：技能 = ID + 组件列表，组合优于继承；新增技能 = 添加组件配置，不改代码；
帧级驱动：帧事件（音效@帧）与判定窗口（伤害@帧区间）以动画帧为时间基准，保证"动画、判定、音效"三者同步——解决动作游戏中判定与表现不一致的经典问题；
生命周期闭环：任何时刻打断技能，系统立即中断并执行清理，不残留判定区/无敌帧污染后续行为；
内嵌序列化：组件用 [SerializeReference] 内嵌于技能资产，编辑器中直接添加、命名、调参，零资产文件操作（策划友好）。

五、关键技术难点与解决方案
 
难点
解决方案
动画与判定不一致（动作游戏核心痛点）
帧事件 + 判定帧窗口，以动画归一化时间驱动判定与音效
技能打断的残留污染
四态生命周期（OnInterrupt 强制清理判定区/无敌帧）+ 运行时自测清单
连击手感（连点抽搐/慢点连不上）
动画进度驱动的连击窗口 + 残响窗口 + 窗口外输入忽视
编辑器修改即时生效
三层架构 + ScriptableObject 资产中介，编辑器与运行时零直接依赖
组件配置的策划易用性
[SerializeReference] 内嵌组件，界面内添加/命名/调参
